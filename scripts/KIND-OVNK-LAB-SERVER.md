## Deployment: values-only + external Helm (UDN)

Primary script:

```bash
cd /root/dpu-simulator
./scripts/deploy-kind-ovnk-values-only.sh
```

### What the script does

1. `make build` (unless `--skip-build`)
2. `./bin/dpu-sim --config config-kind-ovnk-offload.yaml --ovnk-mode values-only` (unless `--skip-infra`)
3. Apply AdminNetworkPolicy / BaselineAdminNetworkPolicy CRDs on the host
4. Helm install/upgrade OVN-K on **host** using:
   - `scripts/ovnk-helm-values-host-udn-base.yaml`
   - `kubeconfig/helm-values/dpu-sim-host-ovn-kubernetes-dpu-host-values.yaml` (generated by dpu-sim)
5. Wait for rollouts, remove host `kube-proxy`
6. `./bin/dpu-sim ovnk host-access` + regenerate DPU Helm values
7. Helm install/upgrade OVN-K on **DPU** using:
   - `scripts/ovnk-helm-values-dpu-udn-base.yaml`
   - `kubeconfig/helm-values/dpu-sim-dpu-ovn-kubernetes-dpu-values.yaml`
8. Resume CoreDNS / local-path-provisioner; verify nodes Ready

### Script options

| Flag | Meaning |
|------|---------|
| `--skip-build` | Use existing `bin/dpu-sim` |
| `--skip-infra` | Skip Kind/dpu-sim deploy; only Helm + post-install (clusters must already exist) |
| `--skip-verify` | Skip final node readiness checks |
| `--cleanup-only` | `./bin/dpu-sim --config config-kind-ovnk-offload.yaml --cleanup` |

Re-run Helm only (clusters already up):

```bash
./scripts/deploy-kind-ovnk-values-only.sh --skip-build --skip-infra
```

Full clean redeploy:

```bash
./scripts/deploy-kind-ovnk-values-only.sh --cleanup-only
./scripts/deploy-kind-ovnk-values-only.sh
```

Logs from background runs: `/root/dpu-simulator/logs/deploy-*.log`

## OVN-K Helm layout (UDN)

**Host cluster** installs three components:

- `ovnkube-control-plane` — cluster manager on control-plane node
- `ovnkube-single-node-zone` — OVN DB on control-plane / non-`dpu-host` nodes (**no** mgmt VF)
- `ovnkube-node-dpu-host` — on `k8s.ovn.org/dpu-host` workers; requests `dpusim.io/mgmtvf`

**DPU cluster** uses:

- `ovnkube-single-node-zone-dpu` — local OVN DB on each DPU node (**not** `ovnkube-node-dpu`, which lacks DB containers and fails on Kind)

Important host values (in base YAML):

- `global.enableNetworkSegmentation: true`
- `global.enablePersistentIPs: false` (avoids requiring IPAMClaims CRD on Kind)
- Egress / ANP feature flags and `mtu: 1400` are in `scripts/ovnk-helm-values-host-udn-base.yaml`

Runtime `--set` overrides (still in script): `k8sAPIServer`, `podNetwork`, `serviceNetwork` for each cluster (Kind control-plane IPs and CIDRs).

## Device plugin

- DaemonSet: `kube-system/dpu-sim-device-plugin`
- Resource pools: `dpusim.io/mgmtvf` (`eth0-1`…`eth0-N`), `dpusim.io/vf` (`eth0-(N+1)`…; `eth0-0` is gateway-only)
- After rebuilding the device-plugin image, load into the **host** Kind cluster and restart:

```bash
cd /root/dpu-simulator
podman build -f deploy/device-plugin/Dockerfile -t dpu-sim-dp:latest .
podman tag dpu-sim-dp:latest localhost/dpu-sim-dp:latest
podman save localhost/dpu-sim-dp:latest -o /tmp/dpu-sim-dp.tar
kind load image-archive --name dpu-sim-host /tmp/dpu-sim-dp.tar
kubectl --kubeconfig kubeconfig/dpu-sim-host.kubeconfig \
  rollout restart daemonset/dpu-sim-device-plugin -n kube-system
```

Verify allocatable resources:

```bash
kubectl --kubeconfig kubeconfig/dpu-sim-host.kubeconfig get nodes \
  -o custom-columns=NAME:.metadata.name,MGMTVF:.status.allocatable.dpusim\\.io/mgmtvf,VF:.status.allocatable.dpusim\\.io/vf
```

## Known pitfalls (from prior runs)

1. **`ovnkube-control-plane` CrashLoopBackOff** — was caused by missing IPAMClaims CRD when `enablePersistentIPs=true` with UDN. Base values now set `enablePersistentIPs: false`.

2. **`ovnkube-node-dpu-host` Pending** — needs `dpusim.io/mgmtvf` on dpu-host workers. Ensure eth0-1 (and mgmt VF range) exist in host Kind nodes and device plugin advertises the resource.

3. **DPU `CreateContainerConfigError` / missing `ovn-config` keys** — DPU Helm must pass `k8sAPIServer`, `podNetwork`, `serviceNetwork` (script does this via `--set`).

4. **DPU pod stuck on `local_dbs_ready`** — use `ovnkube-single-node-zone-dpu`, not `ovnkube-node-dpu`.

5. **Kind image load** — prefer `podman save -o /tmp/image.tar` then `kind load image-archive`; stdin pipe can error with `invalid tar header`.

6. **Server git branch** — checkout on server may lag local branch; sync specific files or `git pull` before testing code changes.
